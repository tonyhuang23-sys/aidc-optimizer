# 二、v2.1 必须优先修正的两个数学问题

## 2.1 CE-NPV 公式与实际计算结果不一致

正文目前定义：

\[
CE\text{-}NPV = E(NPV)-\lambda\cdot CVaR_{95}
\]

同时又定义：

\[
CVaR_{95}=E[NPV\mid NPV\le P5]
\]

但 L4 短缺情景报告：

- \(E(NPV)=-1,406\) M；
- \(CVaR=-2,671\) M；
- \(\lambda=0.5\)；
- \(CE\text{-}NPV=-2,038\) M。

如果严格按照正文公式：

\[
-1,406-0.5\times(-2,671)
=
-70.5
\]

显然与报告值不一致。

根据实际结果，模型真正使用的应是：

\[
\boxed{
CE\text{-}NPV
=
E(NPV)
-
\lambda
\left[
E(NPV)-CVaR^-_{5\%}(NPV)
\right]
}
\]

也可以写成：

\[
\boxed{
CE\text{-}NPV
=
(1-\lambda)E(NPV)
+
\lambda CVaR^-_{5\%}(NPV)
}
\]

以 L4 为例：

\[
0.5\times(-1,406)
+
0.5\times(-2,671)
=
-2,038.5
\]

与正文结果完全一致。

L3 同样：

\[
0.5\times719
+
0.5\times315
=
517
\]

也与正文 CE-NPV = +517 M 一致。

### 建议

正式修改公式，并把 `CVaR95` 改成更加清晰的：

> **Lower-tail Expected Shortfall, \(ES_{5\%}^{-}\)**

或：

\[
CVaR^-_{5\%}(NPV)
\]

因为本文处理的是“收益变量 NPV 的左尾损失”，而不是常规正定义的 loss variable CVaR。

推荐最终写法：

\[
CE\text{-}NPV
=
E(NPV)
-
\lambda
\left[
E(NPV)-ES^-_{5\%}(NPV)
\right]
\]

其中：

\[
ES^-_{5\%}(NPV)
=
E[NPV\mid NPV\le P5]
\]

这样数学定义和经济含义都更加清楚。

## 2.2 IRASR 正文算术与表格数字不一致

正文给出：

\[
IRASR_{L3\rightarrow L4}
=
\frac{-2,038-517}{755-287}
=
-5.82
\]

但按照正文显示的数字：

\[
\frac{-2,555}{468}
\approx -5.46
\]

而不是 -5.82。

### 可能原因

可能使用了程序输出中的未四舍五入原始数值，而正文表格展示的是四舍五入后的结果。

如果是这种情况，不是模型问题，而是报告生成问题。

### 建议

以后所有：

- IRASR；
- ΔNPV/ΔCAPEX；
- CE-NPV；
- Equity NPV；
- DSCR；

都应直接由结果文件自动写入报告，而不要人工重新计算。

建议在正文中使用：

> “基于未四舍五入底层结果，IRASR = X.XX。”

并在脚注说明表格展示值经过四舍五入。

因为 IRASR 是本文自定义的核心指标，不能出现明显算术不一致。

# 三、核心实验目前尚不是真正意义上的“三维矩阵”

论文将核心实验描述为：

> **Asset Stack × Contract Structure × GPU Vintage**

理论上这是：

\[
2\times2\times2=8
\]

个完整 factorial cells。

但目前表格实际包括：

1. Greenfield × Merchant；
2. Greenfield × Contracted；
3. Brownfield × Merchant；
4. Brownfield × Contracted；
5. Brownfield × Contracted × Used H100。

也就是说当前实际上是：

> **2×2 基础矩阵 + 一个附加情景**

还不是严格的三维 factorial experiment。

## 建议方案 A：补齐完整 2×2×2

如果模型计算成本不高，建议直接补成八格：

### Asset Stack
- Greenfield
- Brownfield

×  

### Contract
- Merchant
- Contracted

×  

### GPU Vintage
- Current-generation
- Used previous-generation

完整输出：

| Asset Stack | Contract | GPU | NPV | IRR | CE-NPV | Peak Equity |
|---|---|---|---:|---:|---:|---:|

这样不仅可以观察单一变量，还可以进一步分解：

- Main Effect of Contract；
- Main Effect of Brownfield；
- Main Effect of GPU Vintage；
- Contract × Asset Stack interaction；
- Contract × GPU Vintage interaction；
- Asset Stack × GPU Vintage interaction。

这会明显提高论文的方法论完整度。

## 建议方案 B：如果不补齐

把“三维矩阵实验”改称：

> **Multi-dimensional Scenario Experiment**

# 五、Level C 建议改名，不宜称为严格的 Out-of-sample Validation

v2.0 把验证拆成：

- Level A：Parameter Anchoring；
- Level B：Internal Validation；
- Level C：Out-of-sample Validation。

这个框架方向是正确的。

但目前 Level C 三项内容实际上更接近：

> **External Benchmark / Plausibility Check**

而不是真正意义上的样本外预测验证。

例如：

### C1 GPU系统价

外部：

> DGX B300 $400–500K

模型：

> $480K

这本质是在检查模型输入/成本参数是否落在市场合理范围。

### C2 GPU租金

外部 DigitalOcean H100 按需价格 vs 模型合约/现货中间值。

这同样主要是在验证输入假设。

### C3 债务承载

外部 REIT / JV ND/EBITDA 与项目融资隐含 leverage 比较。

两个口径甚至并不完全一致。

因此当前 Level C 更适合命名：

# Level C — External Benchmark / Plausibility Tests

真正的：

# Out-of-sample Transaction Validation

应该采用：

> **未参与任何参数校准的完整交易案例**

然后让模型预测：

- CAPEX/MW；
- rent；
- NOI；
- leverage；
- DSCR；
- implied valuation；
- sponsor equity requirement。

再比较：

\[
Prediction\ Error
\]

建议未来至少选择 5 笔真实交易作为 v3.0 的样本外验证集。

# 六、Power-only 结果存在潜在的“参数一致性”问题

这是当前模型最值得继续深挖的经济问题之一。

Power-only 基准约：

- CAPEX：$1,150/kW；
- Equity IRR：约28%；
- Project IRR：约21%；
- 损失概率极低。

这一结果可能是真实的，也可能部分来自：

> **低成本二手/中国设备 CAPEX + Greenlight/Meta 级高质量长期 Tolling Rent**

被同时组合进同一个 Base Case。

但是现实中不同资产状态之间存在约束关系。

Greenlight 是：

- 新建大型 CCGT；
- 高可靠性；
- 长期 Meta 级 off-taker；
- 高规格 EPC；
- 长期 OEM / LTSA；
- 大型 dedicated infrastructure。

而 $1,150/kW 的 9E 类低成本配置可能来自：

- 二手机组；
- 较短剩余寿命；
- 不同 heat rate；
- 不同 availability；
- 不同 EPC guarantee；
- 不同 financing bankability。

因此不能自动假设：

> **最低 CAPEX 与最高质量合同能够同时获得。**

## 建议增加 Parameter Coherence Test

至少跑三个 Power Cases：

### P1 New-build CCGT + Hyperscaler Tolling

- 高 CAPEX；
- 高 availability；
- 长期 IG off-taker；
- 低融资利差。

### P2 Used GT + Bridge Contract

- 低 CAPEX；
- 中等 availability；
- 短合同；
- 较高 debt spread；
- 更高 residual / overhaul risk。

### P3 Used GT + Premium Long-term Tolling

- 低 CAPEX；
- 高租金；
- 作为 Upside / Arbitrage Case。

如果 P3 仍然显示显著超额回报，那么它可以成为一个真正有投资价值的：

> **equipment-market / contract-market arbitrage**

但如果只有在 P3 才能得到 28% Equity IRR，就不应把该结果作为 Power-only 的普遍 Base Case。

# 八、Monte Carlo 统计表达还需进一步标准化

v2.0 已经比 v1.0 明显改善，不再简单将“无损失样本”写成 0%。

但以下表述仍需调整：

> 100% [100–100%]

对于有限模拟次数，这在统计意义上不严谨。

如果：

\[
N=1500
\]

且：

\[
1500/1500
\]

都为负，则观察损失率是100%，但真实概率的95%置信区间下界仍低于100%。

同理：

\[
0/1500
\]

也不能说真实风险为0。

## 建议

统一使用：

- Wilson interval；或
- Clopper–Pearson exact interval。

并在每张结果表明确：

\[
N=xxxx
\]

例如：

> 0/1500 observed losses; 95% CI: 0–0.25%

以及：

> 1500/1500 losses; 95% CI: 99.75–100%

另外正文写：

> 每个情景 N≥800

但各表 CI 并不完全对应统一 N，因此最好明确每张表的实际 sample size。

# 九、CE-NPV 本身还需要补一组 λ 敏感性

本文现在选：

\[
\lambda=0.5
\]

这是合理的中性风险厌恶设定，但 λ 本质上是人为选择的 Risk Aversion Parameter。

因此应至少报告：

\[
\lambda=0
\]

\[
\lambda=0.5
\]

\[
\lambda=1
\]

对应：

- Risk-neutral；
- Moderate risk aversion；
- Full tail penalty。

例如：

| Case | CE-NPV λ=0 | λ=0.5 | λ=1 |
|---|---:|---:|---:|
| L3 | E(NPV) | Current CE | Tail ES |
| L4 | E(NPV) | Current CE | Tail ES |

这样可以证明：

> **L3–L3.5 的甜蜜点结论不是 λ=0.5 人为选取的结果。**

这是非常重要的 robustness test。

# 十、IRASR 建议进一步强调其经济含义，而不是只展示公式

IRASR 是本文最有可能形成自己辨识度的指标：

\[
IRASR_i
=
\frac{
\Delta CE\text{-}NPV
}{
\Delta PeakSponsorEquity
}
\]

其经济含义应明确写成：

> **股东每新增投入1美元峰值风险资本，为价值链继续向下一层延伸所创造或毁灭的确定性等价价值。**

这个表达非常强。

建议同时定义三个区间：

### IRASR > 0

下一层创造风险调整后增量价值。

### IRASR ≈ 0

边际延伸，是否进入下一层取决于战略协同。

### IRASR < 0

继续延伸毁灭 Sponsor 风险调整后价值。

这样 IRASR 就从一个公式变成真正的：

# Capital Allocation Decision Rule

# 十一、融资模型中“负Project NPV + 正Equity NPV”值得独立形成一个框架结论

v2.0 对这个问题已经进行了很好的修正：

- Equity IRR 标记 Leverage-distorted；
- Vendor Backstop DSCR < covenant 标记 Not Financeable；
- 增加 Equity NPV、MIRR、MOIC；
- 检查现金流符号翻转。

但这一发现本身值得在讨论部分进一步总结。

可以提出：

# Financing Redistribution ≠ Economic Value Creation

即：

\[
Project\ NPV<0
\]

但：

\[
Equity\ NPV>0
\]

并不表示项目创造价值。

它可能表示：

> **融资合同把项目总价值的一部分从债权人转移给股权。**

因此任何商业模式必须同时检查：

\[
Project\ NPV
\]

和：

\[
Sponsor\ Equity\ NPV
\]

以及：

\[
Debt\ NPV
\]

甚至建议增加：

\[
Total\ Stakeholder\ NPV
=
Equity\ NPV + Debt\ NPV
\]

这对于 GPU / private-credit / vendor-backstop 模式尤其重要。

# 十二、建议将“融资能力”从辅助维度提升为模型核心解释变量

目前五维评价包括：

1. Investment Intensity；
2. Return；
3. Risk；
4. Exposure；
5. Financeability。

建议在论文讨论中进一步强调：

> **Financeability 本身就是资产价值的一部分。**

因为优质合约能够同时：

1. 提高收入确定性；
2. 降低现金流尾部风险；
3. 提高 debt capacity；
4. 降低 sponsor equity；
5. 降低 cost of capital；
6. 创造 refinancing / capital recycling 机会。

因此：

\[
Contract
\rightarrow
Cashflow\ Visibility
\rightarrow
Bankability
\rightarrow
Leverage
\rightarrow
Sponsor\ Capital\ Efficiency
\]

这实际上是 AIDC 与一般科技投资最大的区别之一。
