## 2. “双锚点校准”现在更像Parameter Anchoring，而不是严格意义上的Validation

这是如果让金融/学术审稿人看，最容易被抓住的地方。

比如 TeraWulf–Anthropic：

401 MW × 20年 × $197/kW-month

本身基本就会重现约$19B。如果模型的租金参数就是由这笔交易反推出来，那么模型再输出$19B，严格说属于：

> **calibration / identity check**

而不是：

> **independent validation**

Greenlight也类似。你目前写成“两个公开交易为锚点校准，偏差均可接受”，然后摘要进一步说“双锚点验证了数量级可信度”。

建议正式拆成三级：

**Level A — Parameter Anchoring**
 Greenlight、TeraWulf用于确定合理参数区间。

**Level B — Internal Validation**
 检查：

- Sources = Uses；
- debt roll-forward；
- project CF = equity + debt CF reconciliation；
- terminal debt；
- tax；
- IRR/NPV解析解。

**Level C — Out-of-sample Validation**
 另外找3–5笔**没有用于设参数**的交易，看模型是否能够预测其：

- CAPEX/MW；
- rent；
- leverage；
- NOI；
- implied valuation。

这样论文一下会严谨很多。

而且现在参考文献[8]还是“公开报道口径，经内部框架整理”，这对于论文的两大校准锚点明显不够。最好直接用 **SEC/公司公告/AUC/Pembina/Meta原始文件**。

# 3. 我认为现在最大的概念问题其实在 L5：你把“AI Factory”定义得还不够清楚

如果L5是：

> **拥有模型/IP/客户的OpenAI或Anthropic**

如果L5只是：

> 替别人运行推理的Managed Inference Infrastructure Operator

这两个完全不是一个商业模式。

### L5a Managed AI Compute / Inference Factory

没有模型IP。

收入：

$/token,\quad \$/request,\quad managed\ inference

### L5b Frontier Model / Application Owner

拥有：

- model IP；
- customer；
- API；
- subscription；
- application monetization。

经济指标：

Gross Profit/GPU−hour

甚至：

Incremental Enterprise Value/Compute Dollar

**Meta还应该单列Captive AI模式。**

因为Meta根本不是靠token收入回收AIDC投资。

这一修改会让论文在经济理论上明显更完整。

# 4. L4出现“Project IRR -2.5%，NPV -$1.4B，但Equity IRR +58.6%”，一定要专项解释甚至修改指标

这张表现在很吸睛，但也是论文最大的“模型审稿风险点”。

短缺情景结果为：

- Project IRR -2.5%
- NPV -$1.412B
- Equity IRR 58.6%
- Min DSCR 1.48x
- P(NPV<0)=98%

而Vendor Backstop后 Equity IRR甚至61.1%，但 Min DSCR反而降到0.90x。

数学上有可能发生，但经济上读者一定会问：

> **一个毁灭价值的项目为什么股东IRR 60%？**

这很可能与：

- interim distribution；
- refinancing；
- debt draw；
- GPU refresh capex；
- 多次现金流符号转换

有关。

如果 equity cash flow 出现多次正负号，传统 IRR 本身可能产生多根或严重误导。

### MIRR

### DPI / TVPI

### Peak Equity

### Terminal Debt

### Debt Outstanding @ GPU Refresh

然后在出现：

Project NPV<0

却：

Equity IRR≫0

时自动标记：

> **Leverage-distorted IRR / non-economic IRR**

Vendor Backstop情景 Min DSCR=0.90x，则应该直接标：

> **Not financeable under covenant**

而不是把61.1% Equity IRR作为普通投资收益展示。

这会让融资引擎可信度高很多。

maxPeak Sponsor EquityRisk-Adjusted NPV

ΔCAPEXΔNPV



这实际上又退回到了“项目资产回报”，没有充分利用你最有特色的融资模块。

# Incremental Risk-Adjusted Sponsor Return，IRASR

IRASRi=ΔPeak Sponsor EquityiΔRANPVi

ΔNPV/ΔCAPEX

更符合这篇论文的原创定位。

# 6. “Risk-adjusted NPV”现在还没有真正被定义

### 方法A：Certainty Equivalent

CE-NPV=E(NPV)−λ×CVaR95

或者：

### 方法B：RAROC式

RAROC=Economic CapitalExpected NPV

其中：

Economic Capital=P50−P5

或者Expected Shortfall。

我更喜欢：

Peak Sponsor EquityE(NPV)−λCVaR95

这样你论文题目里面的“风险调整决策”就真正有了数学定义，而不是定性评分。

# 7. Monte Carlo现在需要明显加强

论文示例命令使用：

```
--mc 200
```

如果表3/表4也主要是200次模拟，那么：

> P(NPV<0)=0%

实际上只意味着：

> **200次中没有一次为负。**

并不意味着真实概率是0。

甚至1%也只有2个样本。

所以正式论文建议至少：

### 5,000–10,000 runs

并报告：

- median；
- P5/P25/P50/P75/P95；
- CVaR；
- loss probability confidence interval。

更重要的是，你自己在局限性里已经承认参数独立性假设。

现实中恰恰有非常强的相关性：

GPU rent↑↔GPU residual↑↔GPU purchase price↑

以及：

COD delay↑↔IDC↑↔CAPEX↑

所以v2最好加入：

### Correlation Matrix

至少对：

- GPU rate；
- residual；
- utilization；
- GPU CAPEX；
- DC rent；
- construction cost；
- COD delay

设置相关关系。

这会比简单提高模拟次数更有价值。

# 8. “GPU不赚钱”的结论，现在应该升级成一个2×2资产栈结论，而不是单一价值链结论

> **二手H100是否赚钱，决定因素并不是GPU价格本身，而是资产栈。**

全栈绿地：

Power + Greenfield DC + Rack + GPU

结果深度负NPV；

而已有矿场/棕地：

Power/Building sunk + GPU

经济性完全不同。

我建议正式把它升格为核心实验：

|                                      | Merchant / Spot | Contracted / Take-or-pay |
| ------------------------------------ | --------------- | ------------------------ |
| **Greenfield full-stack**            | Case A          | Case B                   |
| **Brownfield / sunk power+building** | Case C          | Case D                   |

然后再把：

**Vendor Backstop**

作为第三个维度。

这比单纯说：

> L3/L3.5是甜蜜点

高级很多。

> **最优层级不是价值链本身的固定属性，而是Asset Stack × Contract Structure × Capital Structure共同决定的。**
