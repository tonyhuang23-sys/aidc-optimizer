**审阅对象**：`论文_AIDC价值链投资评估模型_工作论文_v6.0.md`  
**审阅结论**：**Major Revision（偏小修方向）**

v6.0 是目前最完整、最成熟的一版。六维资产函数 + Sponsor Access Overlay、All-risk CE、Transfer Pricing、Matched Counterparty、IRASR_econ 和 L4-M/C/S 的边界已经基本形成闭环。下一步不应再扩展框架，而应集中清理旧版本结果、统一口径、提高可复现性与风险参数透明度。


# 一、P0：主文仍保留已知受 Frequency Bug 影响的旧 L4 数字

§6.2 表4仍保留 v3.3 的 L4 NPV **−$3.351B / Peak $1.097B**，虽然脚注说明频率修复后同一 YAML 路径约为 **−$964M**，Headline Merchant 又在后文变成 mix-ref $7.80 下 **+$78M / Peak $2.362B**。

2. 旧 −$3.351B 只移入附录“Version Audit”，用于解释 Frequency Bug。
3. 正文所有“基准结果”只保留当前引擎结果。

这是正式发布前必须完成的清理。


# 二、P0：2×2×2 因子实验仍是 Frequency Bug 前结果，必须完整重跑

§6.3 仍沿用旧八格结果，并据此给出：

\[

\]

但该实验的 Merchant / Contracted rent decay 本身正是 Frequency Bug 所影响的变量。因此即使排序方向可能保留，**+$1.45B、+$0.91B、+$0.23B 和 −$0.446B interaction 都不能继续被视为 v6.0 的有效数值证据。**

建议新增 `research_v6_factorial_fixed.py`，在正确 `(1+g)^(month/12)` 路径下完整重跑：
- 8格 NPV；
- Project IRR；
- Peak Equity；
- CE；
- 主效应；
- 交互项。

重跑前，论文只能写“旧实验曾显示……，频率修复后正在重估”，不能继续把旧效应量作为正式结论。


# 三、P0/P1：IRASR_econ 已成为主指标，但 Economic Capital 仍未校准

论文把：

\[
IRASR_{econ}=\Delta CE/\Delta Sponsor\ Economic\ Capital
\]

提升为主资本配置指标，这是正确方向；但正文同时承认 EconCap 中 guarantee / LC / reserve 仍为筛选比例假设。

这会形成明显张力：**主指标最重要的分母仍是 prototype。**

建议：
- 将 `GuaranteeEq` 改为风险等价值，而不是简单名义额相加；
- 避免 LC / reserve / completion support 双计；
- 至少给 EconCap Low / Base / High 三档；
- 在完成校准前，主文措辞改成：

> “IRASR_econ 是理论首选指标；本文以筛选级 Economic Capital 估算，并同时报告 Peak Equity 口径交叉验证。”

这样 C ≈ +0.72、S ≈ +1.29 才不会被误读为过度精确。


# 四、P1：All-risk MC 统一成功，但 N=800 不应成为最终外部 Headline

当前统一 All-risk 已是重大进步，但 N=800 时，5% ES 实际只由约40个尾部样本决定。由于正文 λ=0.5，CE 的一半权重来自这40个样本。

建议正式版直接跑：

\[
N=10,000
\]

并固定：
- random seed；
- parameter version；
- code commit hash。

此外，Bootstrap CI 只表示**既定模型假设下的模拟抽样误差**，并不包含：
- $7.02成交价不确定性；
- PD/LGD估计误差；
- residual / correlation；
- EconCap；
- CAPEX calibration。

建议把“Bootstrap 95% CI”改称：

> **Simulation Bootstrap Interval, conditional on model assumptions**

并明确它不是“真实项目价值的95%置信区间”。


# 五、P1：WACC + CE 的风险重复问题仍需更谨慎

正文写“WACC补偿系统性风险、ES补偿项目特异左尾，二者不重复”。这个判断过强。

All-risk MC 中的 GPU rent、residual、credit、refinancing 都可能具有系统性成分。如果这些风险既进入较高 WACC，又进入左尾分布，就可能存在部分 double counting。

建议正文改成：

> 本文意图用WACC表达长期资本要求，用CE表达Sponsor对模拟左尾的偏好；部分市场变量可能同时具有系统性与项目特异性，无法完全排除风险调整重叠。

最好增加稳健性表：
- A：分层 WACC + λ=0；
- B：统一未杠杆贴现率 + CE；
- C：分层 WACC + CE（正文）。

若 C/S > L3 > M 在三种口径下均成立，方法争议会明显降低。


# 六、P1：Matched Counterparty 中 L3 +248 与 Headline +299 需解释

表9-3：L3 Generic tenant = **+$248M**，IG = **+$402M**。

# 七、P1：Transfer Pricing 是论文亮点，但 $185/kW-month 应做敏感性

“Sunk Cost ≠ Zero Opportunity Cost”是 v6.0 最重要的新结论之一。

但 $185/kW-month 是特定 Critical Capacity Revenue 量级，不应被视为所有市场的统一 L3机会成本。

建议测试：

- $125/kW-month
- $150
- $185
- $225
- $250

并重新求：

\[
R^{GPU-only}_{CE-parity}=f(L3\ transfer\ rent)
\]

当前经济口径约 $11.32/GPU-h 的结论很有价值，但最好呈现成一条曲线/表，而不是单点。


# 八、P1：Access Probability 的 1%–1.5% 阈值需要加入“时间和选择权成本”

当前：

\[
p^*=PursuitCost/(CE_C-CE_{L3})
\]

若 PursuitCost=$20M，得到约1%–1.5%的成功率阈值，数学上没问题，但现实中 pursuit cost 不只是现金顾问费。

应包括：
- 6–24个月等待；
- land carrying；
- utility deposits；
- reserved equipment；
- design freeze；
- exclusivity；
- lost alternative tenant；
- COD delay；
- management bandwidth。

建议：

\[
PursuitCost=CashCost+DelayCost+OptionValueLost+CommittedCapacityCost
\]

至少跑：
- $20M / 6个月
- $50M / 12个月
- $100M / 18个月
- $200M / 24个月

这样 p* 才能变成真正可用于开发决策的指标。

# 十三、P2：CE-NPV最好明确叫“自定义确定性等价代理”

严格理论中的 certainty equivalent 一般来自明确效用函数或风险调整概率。

本文：

\[
CE=(1-\lambda)E+\lambda ES_5
\]

更准确地说是：

> **tail-weighted certainty-equivalent proxy**

建议首次定义时写：

> “本文定义一个自定义确定性等价代理（CE-NPV）……”

这样可以减少学术审稿人对术语的争议。

# 十九、建议保留的最终核心句

> **同一张GPU并不存在固定的“基础设施属性”。在Merchant结构下，它是高折旧、高波动的技术资产；在长期take-or-pay支持下，它成为Contract-backed Compute Asset；在客户信用、Vendor Support与机构融资共同作用下，它才进一步转化为可融资的AI基础设施资产。**

> **AI基础设施投资的真正问题不是“价值链哪一层收入最高”，而是在特定Investment Vintage、Asset Stack与Contract条件下，每增加一美元Sponsor Economic Capital，能够获得多少新增风险调整价值。**
